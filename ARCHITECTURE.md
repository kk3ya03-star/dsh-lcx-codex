# LCX architecture — 0.6.0-pre.2

This prerelease targets the DSH 0.2.1 contract. Its verified baseline is exactly **DSH 0.2.1-alpha.2, Session V4, host Pi 1.1.0 and plugin Pi 1.1.0**. Public DSH peers use a lower-bound-only `>=0.2.1-alpha.2` install range (no upper bound): newer DSH versions can install it but are unverified and need their own compatibility evidence. The stable `0.5.x` line targets DSH 0.2.0-rc.2 with host and plugin Pi 0.87.1 and keeps its own copy of this file on its branch; the plugin always bundles the same Pi version the targeted DSH runs on (DSH's own copy of Pi is not reachable by plugins, which is the only reason Pi is bundled at all). This is a model-scoped plugin, not a replacement DSH runtime.

## Ownership and package boundary

- **DSH** owns provider/model configuration, credentials, agents, tools, session persistence and migration, attachments, compaction ranges, durable transactions and context-pressure measurement.
- **LCX** owns the enabled GPT Responses final request/transport/replay path and the bounded Grok native-search bridge. Unrelated model routes retain DSH behavior.
- **Pi 1.1.0 public exports (the same Pi as the host)** supply canonical Responses serialization/stream helpers and model data. A reproducible build bundles the needed runtime subset; the plugin does not ship the complete Pi SDK dependency tree into user profiles or replace host Pi.
- **The browser client** supplies settings, search-media presentation and auxiliary usage presentation. Presentation controls do not change model requests, tools, history, usage or cache semantics.

`src/**` is strict TypeScript source. `lib/**` contains 66 reproducible generated files; the npm allowlist yields a 42-file package with selected declarations, host/client JavaScript, the plugin patch, license/notices, package metadata, README, the Plugin Manager icon and the two locale files. Tests, test fixtures and build scripts remain repository-only. No DSH Core patch or private control-plane material is included. Third-party licensing is in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Module layout

`src/**` (host side, strict TypeScript) is organised by responsibility:

- **Entry and DSH seams**: `index.ts` (plugin entry: settings, `llm/stream` interception, tool registration, lifecycle), `dsh-compat.ts` (the session/tool-runtime seam), `dsh-responses.ts` (DSH message and option projection into the Responses path), `invocation-policy-scope.ts`, `service-mutex.ts`.
- **Route and model facts**: `route.ts` (route resolution, credentials, headers), `provider-headers.ts` (the per-request headers Pi's own client adds for GitHub Copilot and OpenCode), `model-catalog.ts` (what the bundled Pi catalog says about a model), `pi-responses-runtime.ts` (the one file that re-exports the Pi runtime surface the build bundles), `tool-surface.ts` (addition-only versus complete tool lists).
- **Request, stream and transport**: `responses-request.ts`, `responses-stream.ts`, `transport.ts` (bounded HTTP with one retry core, and the one SSE event reader that both the Responses stream and the shared consumers use), `abort-error.ts`, `token-budget.ts`.
- **Compaction and replay**: `compact-v2.ts`, `native-checkpoint.ts`.
- **Search**: `web-search-hosted.ts`, `web-search-alpha.ts`, `web-search-alpha-history.ts`, `web-search-capability.ts`, `web-search-ref-store.ts`, `web-run-output.ts`, `grok-native-search.ts`, `search-accounting.ts`, `search-usage.ts`, `auxiliary-usage.ts`.
- **Shared helpers**: `util.ts` (value guards, coded errors), `defaults.ts` (the numeric defaults of settings and transports, defined once), `json-store.ts`.
- **Browser client** (`src/client/**`, separate TypeScript program): `index.tsx` (conversation/settings registration), `search-media.ts` and `inline-media.ts` (media presentation), `search-usage-ui.ts`, `nested-calls.ts` (settlement of tools called from a `run_code` program).

## Route resolution

LCX takes a request only for a GPT or Grok model whose DSH provider profile resolves to an authenticated OpenAI Responses route; everything else stays on DSH. The profile is the first authority and the bundled catalog fills in what the profile does not say:

1. **Provider profile.** A nonempty `models` list is authoritative: DSH serves exactly the listed models, so a model outside the list is not claimed: the call passes to DSH, which answers `UNKNOWN_MODEL` on GPT and Grok alike, and LCX sends nothing. The profile's `api`, `baseURL`, credentials, headers, `compat` and per-model `reasoningEfforts` win over everything below.
2. **Bundled Pi catalog, exact model.** When the profile does not name a protocol, the provider's catalog entry for that exact model id supplies protocol, endpoint and the wire descriptor.
3. **Provider-shared protocol.** For a model the catalog has not caught up with but DSH serves anyway (the profile lists it, or DSH's own newer catalog resolves it), the single protocol and endpoint every model of that provider agrees on applies, exactly as DSH's own adapter derives it. Host recognition is remembered per plugin context and bound to a fingerprint of the profile, so a live profile change drops it. LCX does not wait for a first request to learn this: at start and whenever the provider configuration or provider set changes it asks DSH once per provider that lists no `models` (`listModels`), and when the answers change it re-synchronises the registered tools, so a model only a newer DSH catalog knows already has the LCX tools on its first request.
4. **Otherwise fail closed.** A model whose protocol neither the profile, the bundled catalog nor DSH resolves gets `LCX_RESPONSES_API_UNRESOLVED` with an instruction to set `api: openai-responses`; nothing is guessed. The former frozen Pi 0.86 allowlist no longer exists. `NO_ADAPTER` is left for routes LCX owns but cannot serve (an explicit non-Responses `api`, or a catalog provider used without an `apiKeyEnv`, which only DSH's own authentication could serve).
5. **Provider decoration.** On every route the catalog model's own `headers` apply under the profile's (a profile header wins whatever its case; DSH attribution replaces the catalog `User-Agent`, as in the host adapter). `github-copilot` additionally gets Pi's Copilot request headers (`X-Initiator`, `Openai-Intent`, `Copilot-Vision-Request`) and `opencode` / `opencode-go` the `x-opencode-session` routing header, both built by Pi's own helpers. `cloudflare-ai-gateway` is not claimed at all: its endpoint ids and `cf-aig-authorization` authentication are performed only by Pi's client, so DSH serves those calls.

Capabilities DSH declares for the exact routed model (image input, reasoning efforts, system-prompt and tool update modes) are read from DSH's model information and applied over the catalog.

## What LCX owns and what it reuses

LCX reuses DSH public APIs and the bundled Pi wherever they already do the work, and owns only what neither provides:

| Reused | Owned by LCX |
| --- | --- |
| DSH: provider profiles, credentials (`assertUsableApiKey`), model information, session log and Session V4 history, tool runtime, compaction engine and transactions, pressure measurement, settings persistence, request-error boundary (`isContextWindowExceededError`), client slots and `ImageLightbox` | The final GPT/Grok Responses request, transport and replay on enabled routes; the route-resolution rules above |
| Pi: canonical Responses message and tool serializer, stream parser, `clampOpenAIPromptCacheKey`, model catalog | Native V2 compaction request and the `lcx-native-compaction-v5` checkpoint lifecycle; remote-first pressure coordination |
| | Hosted and Alpha search tools, Grok native search bridge, search accounting and presentation |

## GPT lifecycle and compaction

The compatibility layer projects exact DSH generate options, attachments and Session V4 history into the Pi-assisted Responses path, including DSH `role: 'tool'` messages (multi-step, error and image results) and dynamic tool changes. Routes that declare in-history system-prompt updates receive a changed system prompt as a later model-role message at its original history position; superseded prompt snapshots are dropped from retained checkpoint items (identified by message provenance, not text) and from portable replay. If the route's model facts cannot be read while such a snapshot is in the history, the request fails closed rather than sending the instruction as user text. Ordinary generation, Native V2 compaction, same-route replay and portable route migration share the request builder. Native V2 uses a Responses request with a compaction trigger; it is not an implementation of every upstream compaction API. DSH's current compaction directive is excluded from Native input.

DSH retains engine/range/transaction ownership and its own pressure trigger. LCX coordinates compatible GPT pressure handling against DSH's pressure budget (`window - output reserve - headroom`): remote-first near 90%, emergency pruning allowed at 95%. DSH may compact first when its own trigger fires. Grok remains on DSH compaction.

Current `lcx-native-compaction-v5` state lives in the DSH session log's compaction result, not a second session database. Opaque replay requires a compatible route/model and the same session identity; cross-session or incompatible-route continuation uses validated portable history instead of another session's opaque state. When DSH 0.2 migrates an older session, LCX does not convert a previous-format checkpoint: on the LCX path it reports `LCX_CHECKPOINT_UNSUPPORTED` and a new session is required. Quoted checkpoint markers inside ordinary tool output are not treated as checkpoints. Retained client history and opaque provider state remain distinct from visible checkpoint text.

The shared transport bounds responses, cleans up streams on failure/cancellation and follows the DSH request-error boundary for ordinary requests. Native compaction retains bounded retry and eligible first-checkpoint fallback. Reopening a persisted DSH session restores compatible state; this is not Codex process-level rollout/restart-resume.

## Search, replay and accounting

GPT ordinary search keeps the host's single `web_search` surface. Advanced Hosted controls and Alpha remain separate tools, and scoped tools are re-synchronized when a session's selected model/route changes, so the next request advertises the correct set. Active invocation scope supplies the calling route; no plugin-owned credential or model fallback is invented. Blank or irrelevant optional Hosted arguments (for example an empty location or image settings without image search) are treated as omitted; invalid non-empty values still fail closed.

Tool updates follow the host. On GPT Responses routes where DSH declares `toolUpdate: "addition-only"` (catalog models that support `additional_tools` or `tool_search`) and the route compat states which shape the model supports (the bundled catalog, or the profile), the request `tools` stay anchored to the initial declarations and a tool added mid-session is declared in history position as an `additional_tools` item (`tool_search` call/output when that is all the model supports). A compat that is silent about both shapes is never guessed at: the complete tool list is sent. LCX re-verifies the host projection and falls back to the complete current tool list when the DSH tool history or model information is missing, the route is not addition-only, the compat is silent or explicitly opts out, or deferred and retained additions disagree; Grok routes, portable replay (fork and route migration) and native compaction checkpoints always send the complete list. Removal and same-name redefinition follow host semantics and cost one cache reset. A settings switch (on by default) turns the behaviour off. The plugin also reads the nested `tool/ptc-dispatch` settlement of `run_code` programs so searches made from code are counted and their media shown, and ships `locale/*.json` and `icon.svg` so the Plugin Manager card shows its own title, description and icon.

Grok native search adds xAI server-side `web_search` / `x_search`, suppresses the duplicate DSH `web_search` for that request, and preserves other local tools. Ordered provider-native output is stored for same-session/route continuation and cold reopen; server search is never represented as a fake local DSH tool call. API-key/API-gateway authentication is supported; OAuth subscription login is not.

Grok agentic calls report provider usage that is cumulative across internal server-side requests. LCX keeps that canonical usage and DSH turn accounting unchanged. For context pressure, when an aggregate-scoped terminal response carries complete `usage.context_details`, LCX anchors pressure on `context_details.input_tokens` plus DSH's own signed surface delta and records provider provenance; otherwise it falls back to a retained-surface plus tool-schema estimate. Because DSH 0.2 has no provider-exact baseline kind, the measurement is exposed to DSH as `estimated`. GPT auxiliary search billing is persisted separately from main-call usage and supplements UI totals without adding model content or pressure.

Alpha stores session/route-scoped reference provenance and rejects conflicting observations atomically. Stateful search, open, find, click, PDF screenshot, cold-process continuation, fork isolation and model-route switching are validated on the tested OAuth-backed upstream; API-key upstream accounts are outside that claim. A target-page fetch failure is reported as `LCX_ALPHA_PAGE_FETCH_FAILED` rather than as missing capability. A search-only backend and a real provider result crossing the spill threshold were not covered at runtime; deterministic spill/cold-locator coverage passes. References are not guessed or replaced with URLs to conceal failure.

## Client presentation and current limits

Search media follows a fixed ownership boundary. DSH owns Markdown images and its image lightbox; LCX adds one scoped CSS rule so a Markdown image in an answer starts its own line, independent of the preview setting. With previews enabled, LCX renders structured provider image candidates and plain direct image links from the answer as one image rail under the owning response (natural proportions, sideways scrolling, DSH's public `ImageLightbox` with an LCX dialog fallback) and direct playable video URLs as cards that load nothing until clicked and then play inline. Page links stay ordinary links and Markdown images are never duplicated. Owned observers, listeners, dialogs and players are disposed when the feature is disabled or the client fiber is disposed. Request-invariance tests cover the UI boundary.

Search-usage presentation installs into DSH's public client slots and fails closed on absent or unsupported shapes, restoring only what it owns. Changing host profile inventory does not recompose an already-open browser boot graph; reload remains required. Dynamic-tool cache deltas and a typed provider-context provenance seam for pressure remain upstream DSH compatibility limits.

## Validation

This tree is checked by 714 plugin tests in 77 test files (`npm test`), strict host and client types (also clean under `--noUnusedLocals --noUnusedParameters`), 4/4 schemas and a clean TypeScript rebuild that must reproduce all 66 generated `lib/**` files byte for byte (`scripts/check-generated.mjs`); the npm package built from it has 42 files. Bounded real-runtime GPT workflows on DSH 0.2.1-alpha.2 (system-prompt updates, tool toggles including a live addition-only A/B, compaction, restart, fork, lifecycle, web search, inline search media, searches made from `run_code`, the Plugin Manager card, and route resolution for models the bundled catalog does not describe, including live profile changes) complement them. Grok native search and user image input received only a limited regression check, and Alpha search and the naturally triggered compaction pressure band were not part of that runtime pass. Capabilities listed above as not covered are excluded from success claims. See the [README](README_EN.md) for installation.
