# LCX architecture — 0.7.0

This release targets the DSH `0.2.2` contract for npm `latest`: its exact build baseline is **DSH 0.2.2-rc.5, Session V4, host Pi 1.6.0 and plugin Pi 1.6.0** (the Pi a fresh DSH install resolves; `scripts/link-dsh-runtime.mjs` fails closed when the two differ). Public DSH peers use the bounded stable install range `>=0.2.2-rc.5 <0.2.3-0` (excluding `0.2.3` prereleases under DSH's `includePrerelease` semver evaluation): later `0.2.2` builds can install it but are unverified until assessed on that exact baseline. The `0.6.0` line remains on `stable/0.6.x` for DSH `0.2.1-rc.5`, the `0.5.x` line remains on `stable/0.5.x` for DSH `0.2.0-rc.2` (Pi `0.87.1`), and `0.7.0-pre.1` remains immutable prerelease history on `@prelatest` (DSH `0.2.2-alpha.3`, Pi `1.5.0`). The plugin always bundles the same Pi version the targeted DSH runs on (DSH's own copy of Pi is not reachable by plugins, which is the only reason Pi is bundled at all). This is a model-scoped plugin, not a replacement DSH runtime.

## Ownership and package boundary

- **DSH** owns provider/model configuration, credentials, agents, tools, session persistence and migration, attachments, compaction ranges, durable transactions and context-pressure measurement.
- **LCX** owns the enabled GPT Responses final request/transport/replay path and the bounded Grok native-search bridge. Unrelated model routes retain DSH behavior.
- **Pi 1.6.0 public exports (the same Pi as the host)** supply canonical Responses serialization/stream helpers and model data. A reproducible build bundles the needed runtime subset; the plugin does not ship the complete Pi SDK dependency tree into user profiles or replace host Pi.
- **The browser client** supplies settings, search-media presentation, read-only per-turn prompt-cache hit-rate presentation, and auxiliary usage presentation. Presentation controls do not change model requests, tools, history, usage or cache semantics.

`src/**` is strict TypeScript source. `lib/**` contains reproducible generated files; `scripts/pack-local.mjs` stages the curated public export tree (excluding private control-plane `README.md`) to yield the 41-file local package (42-file distribution package once the reviewed public `README.md` is overlaid on the distribution surface) with selected declarations, host/client JavaScript, the plugin patch, license/notices, package metadata, the Plugin Manager icon and the two locale files. Tests, test fixtures and build scripts remain repository-only. No DSH Core patch or private control-plane material is included. Third-party licensing is in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Module layout

`src/**` (host side, strict TypeScript) is organised by responsibility:

- **Entry and DSH seams**: `index.ts` (plugin entry: settings, `llm/stream` interception, tool registration, lifecycle, deduplicated Grok budget warnings), `dsh-compat.ts` (the session/tool-runtime seam), `dsh-responses.ts` (DSH message and option projection into the Responses path), `invocation-policy-scope.ts`, `service-mutex.ts`.
- **Route and model facts**: `route.ts` (route resolution, credentials, `session-id` / `promptCacheKeyMode` / `llm-pi-ai/request-headers` handling, `diagnoseGrokContextBudget`), `provider-headers.ts` (the per-request headers Pi's own client adds for GitHub Copilot and OpenCode), `model-catalog.ts` (what the bundled Pi catalog says about a model), `pi-responses-runtime.ts` (the one file that re-exports the Pi runtime surface the build bundles), `tool-surface.ts` (addition-only versus complete tool lists, including silent pass-through for tool-less one-shot requests).
- **Request, stream and transport**: `responses-request.ts`, `responses-stream.ts`, `transport.ts` (bounded HTTP with one retry core, and the one SSE event reader that both the Responses stream and the shared consumers use), `abort-error.ts`, `token-budget.ts`.
- **Compaction and replay**: `compact-v2.ts`, `native-checkpoint.ts`.
- **Search**: `web-search-hosted.ts`, `web-search-alpha.ts`, `web-search-alpha-history.ts`, `web-search-capability.ts`, `web-search-ref-store.ts`, `web-run-output.ts`, `grok-native-search.ts`, `search-accounting.ts`, `search-usage.ts`, `auxiliary-usage.ts`.
- **Shared helpers**: `util.ts` (value guards, coded errors), `defaults.ts` (the numeric and volatile setting defaults, defined once), `json-store.ts`.
- **Browser client** (`src/client/**`, separate TypeScript program): `index.tsx` (conversation/settings registration, including `gatewayCompatibilityFallback`), `search-media.ts` and `inline-media.ts` (media presentation), `search-usage-ui.ts` (auxiliary usage slots and read-only per-turn cache hit-rate pill), `nested-calls.ts` (settlement of tools called from a `run_code` program).

## Route resolution

LCX takes a request only for a GPT or Grok model whose DSH provider profile resolves to an authenticated OpenAI Responses route; everything else stays on DSH. The profile is the first authority and the bundled Pi 1.6.0 catalog (91 credential-only owned GPT/Grok Responses pairs across `openai`, `opencode`, `opencode-go`, `github-copilot`, and `xai`, out of 116 GPT/Grok Responses pairs within 135 total `openai-responses` entries across the 6 bundled catalogs, excluding 25 host-auth `cloudflare-ai-gateway` pairs delegated to DSH; adding `gpt-6.2-sol`, `gpt-6.2-astra`, and `gpt-6-cyber`) fills in what the profile does not say:

1. **Provider profile.** A nonempty `models` list is authoritative: DSH serves exactly the listed models, so a model outside the list is not claimed: the call passes to DSH, which answers `UNKNOWN_MODEL` on GPT and Grok alike, and LCX sends nothing. The profile's `api`, `baseURL`, credentials, headers, DSH-offered `compat` (`supportsDeveloperRole`, `supportsMaxOutputTokens`, `supportsStrictMode`, `supportsLongCacheRetention`), and per-model `reasoningEfforts` win over everything below, while LCX's own `Config.promptCacheKeyMode` (`"auto" | "disabled" | "enabled"`) can override the catalog prompt-cache-key mode across chat, compaction, Hosted Search, and Grok.
2. **Bundled Pi catalog, exact model.** When the profile does not name a protocol, the provider's catalog entry for that exact model id supplies protocol, endpoint and the wire descriptor.
3. **Provider-shared protocol.** For a model the catalog has not caught up with but DSH serves anyway (the profile lists it, or DSH's own newer catalog resolves it), the single protocol and endpoint every model of that provider agrees on applies, exactly as DSH's own adapter derives it. Host recognition is remembered per plugin context and bound to a fingerprint of the profile, so a live profile change drops it. Pre-warm (`listModels`) and optimistic first-request tool ownership work together so host-only models already carry LCX tools on turn 1.
4. **Otherwise fail closed.** A model whose protocol neither the profile, the bundled catalog nor DSH resolves gets `LCX_RESPONSES_API_UNRESOLVED` with an instruction to set `api: openai-responses`; nothing is guessed. `NO_ADAPTER` is left for routes LCX owns but cannot serve (an explicit non-Responses `api`, or a catalog provider used without an `apiKeyEnv`).
5. **Provider decoration and session affinity.** On every route the catalog model's own `headers` apply under the profile's (a profile header wins whatever its case; DSH attribution replaces the catalog `User-Agent`, as in the host adapter). Following Pi 1.6.0, `sessionAffinityFormat === "openai"` emits hyphenated `session-id` (replacing `session_id`) plus `x-client-request-id`, `openai-nosession` omits `session-id` while keeping `x-client-request-id`, and `openrouter` emits `x-session-id`. When `promptCacheKeyMode === "disabled"`, LCX omits `prompt_cache_key` from standard, Native V2 compaction, Hosted Search, and Grok request bodies while keeping `session-id` affinity and prompt-cache retention fields. `github-copilot` gets Pi's Copilot request headers (`X-Initiator`, `Openai-Intent`, `Copilot-Vision-Request`) and `opencode` / `opencode-go` get `x-opencode-session`. `cloudflare-ai-gateway` is left to DSH.
6. **Grok budget pre-flight diagnostic.** On agent instrumentation, session selection changes, settings updates, and non-title `llm/stream` calls, `diagnoseGrokContextBudget` / `diagnoseGrokContextBudgetAsync` inspects Grok routes via unified `isGrokModelId` (matching `grok-*`, `x-ai/grok-*`, and camelCase `grokCustom`/`GrOkCustomPreview`, while excluding non-Grok models like `vendor/grokking` or `agrok-4.7`) using DSH `resolveModelInfo` (`context.contextWindow`, `defaultMaxTokens`), profile `models[]`/`modelOverrides` `maxTokens`, and upcoming request `maxTokens` precedence, and emits a single deduplicated warning per scope/context when `maxTokens >= contextWindow` (which DSH `0.2.2` blocks on model switch with `MODEL_SWITCH_COMPACTION_FAILED`).

Capabilities DSH declares for the exact routed model (image input, reasoning efforts, system-prompt and tool update modes) are read from DSH's model information and applied over the catalog.

## What LCX owns and what it reuses

LCX reuses DSH public APIs and the bundled Pi 1.6.0 exports wherever they already do the work, and owns only what neither provides:

| Reused | Owned by LCX |

## GPT lifecycle and compaction

The compatibility layer projects exact DSH generate options, attachments and Session V4 history into the Pi-assisted Responses path, including DSH `role: 'tool'` messages (multi-step, error and image results) and dynamic tool changes. For a catalog model whose compat states `supportsMidConvoEffort` (the GPT-6 models on `openai`), an ordinary request with a reasoning level keeps `reasoning.effort` at `medium` and sends the level as `configuration_update` input items, before each same-model reply that recorded its level (`providerThinkingLevel` in the replay state, written and read like the host) and once at the end of the input, so an effort change keeps the cached prefix; Sign in with ChatGPT keys, compaction, Grok requests, and requests with `gatewayCompatibilityFallback: true` keep the standard top-level `reasoning.effort`. Routes that declare in-history system-prompt updates receive a changed system prompt as a later model-role message at its original history position (preserved even when `gatewayCompatibilityFallback: true`); superseded prompt snapshots are dropped from retained checkpoint items (identified by message provenance, not text) and from portable replay. If the route's model facts cannot be read while such a snapshot is in the history, the request fails closed rather than sending the instruction as user text. Ordinary generation, Native V2 compaction, same-route replay and portable route migration share the request builder. Native V2 uses a Responses request with a compaction trigger; DSH's current compaction directive is excluded from Native input.

DSH retains engine/range/transaction ownership and its own pressure trigger. LCX coordinates compatible GPT pressure handling against DSH's pressure budget (`window - output reserve - headroom`): remote-first near 90%, emergency pruning allowed at 95%. DSH may compact first when its own trigger fires. Grok remains on DSH compaction.

Current `lcx-native-compaction-v5` state lives in the DSH session log's compaction result, not a second session database. Opaque replay requires a compatible route/model and the same session identity; cross-session or incompatible-route continuation uses validated portable history instead of another session's opaque state.

## Search, replay and accounting

GPT ordinary search keeps the host's single `web_search` surface. Advanced Hosted controls and Alpha remain separate tools, and scoped tools are re-synchronized when a session's selected model/route changes.

Tool updates follow the host by default (`gatewayCompatibilityFallback: false`). On GPT Responses routes where DSH declares `toolUpdate: "addition-only"` and the route compat states which declaration item the model supports, the request `tools` stay anchored to initial declarations and mid-session additions render as `additional_tools` items (`tool_search` when that is all the model supports). Tool-less one-shot internal calls (such as DSH `auto-review`) with no `tools`, no `toolHistory`, and no `developer` updates take a clean zero-tool pass-through in `planToolSurface` without emitting fallback warnings. When `gatewayCompatibilityFallback: true` is opted in via settings, LCX forces full tool projection and suppresses `additional_tools`/`tool_search` and `configuration_update` items so standard top-level `tools` and `reasoning.effort` are sent while keeping live OFF/ON toggling, Native V2 compaction, and portable replay consistent. LCX-owned GPT and compaction requests run the host's `llm-pi-ai/request-headers` waterfall in host order while protecting credential, `session-id` / `session_id` / `x-session-id`, correlation, and `x-opencode-session` headers against contributor spoofing.

Grok native search adds xAI server-side `web_search` / `x_search`, suppresses duplicate DSH `web_search` for that request, and preserves other local tools. Ordered provider-native output is stored for same-session/route continuation and cold reopen. API-key/API-gateway authentication is supported; OAuth subscription login is not.

For context pressure on Grok agentic calls, Issue `#62` (`dsh-token-meter` typed provider-context occupancy baseline) remains `OPEN` (`UPSTREAM_SEAM_REQUIRED`) on DSH `0.2.2-rc.5` (`lib/index.js` is byte-identical to `0.2.2-alpha.3`), so `installSearchMeasurement` and `provider-context-details` mitigation stay active.

Alpha stores session/route-scoped reference provenance and rejects conflicting observations atomically.

## Client presentation and current limits

Search media follows a fixed ownership boundary. DSH owns Markdown images and its image lightbox; on DSH `0.2.2-rc.5`, Issue `#105` (DSH Discussion #8443) remains present in `dsh-web-frontend`, so LCX retains `nativeMarkdownImageCss` so standalone Markdown images start on their own line, independent of the preview setting. With previews enabled, LCX renders structured provider image candidates and plain direct image links from the answer as one image rail under the owning response (natural proportions, sideways scrolling, DSH's public `ImageLightbox` with an LCX dialog fallback) and direct playable video URLs as inline cards.

Usage presentation installs into DSH's public client slots (`conversation.chat.turnTail` and `conversation.composer.dock`) and fails closed on absent or unsupported shapes:

- In `conversation.chat.turnTail`, `TurnTailUsage` displays turn search usage (`lcx-search-usage`) and a strictly read-only per-turn prompt-cache hit-rate pill (`Cache XX%` / `缓存命中 XX%`) derived from DSH's `turn.data.get('turn-tail')?.tokenUsage` via overflow-safe integer rounding (`promptCacheHitRate`).
- In `conversation.composer.dock`, `SessionUsage` remains auxiliary-search-only because `dsh-client-ui-chat` `UsagePill` already renders session cache hit percentage.

Changing host profile inventory still does not recompose an already-open browser boot graph; reload remains required.
